# Release lessons

This log records incidents from production releases and the change that prevents each one. Add an entry after every release. The ordered procedure is in the [release operator runbook](../scripts/production/release/README.md). Operational history stays in the [production handoff](production-handoff.md).

## 1.21 server release, 2026-10-19

| Incident                       | Symptom                                                                                   | Cause                                                                                                                                                                                                                 | Prevention                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Artifact download stall        | The `gh` artifact download stalled for about 10 minutes, then failed with a network error | The long single stream had to restart from zero on this network path                                                                                                                                                  | `artifact.py download`: 4 MiB ranges, each with retries and a `Content-Range`/length check. Kept ranges are reused on re-run. The VPS can also fetch the zip directly; `artifact.py vps-download-command` prints the command, and `stage.py --remote-artifact-zip` accepts that zip only when its archive hash matches the hash signed and verified on the Mac |
| Bytecode in the signed release | Staging failed with `verify_bundle`: "Bundle file list changed"                           | The staging script imported `apply-release.py` from the release directory. Python wrote `scripts/production/__pycache__/*.pyc` into the checksummed tree                                                              | Remote steps run as `python3 -B -I` with `sys.dont_write_bytecode` set. `stage.py` executes the updater's source and never imports it. It fails if any `__pycache__` appears. Covered by a unit test                                                                                                                                                           |
| SSH dropped during migration   | The session ended mid-migration. The result was recovered only from server-side logs      | The step was tied to the SSH pipe and kept its result only in local stdout                                                                                                                                            | `remote_step.py` runs each step detached, with file stdio. It writes the exit status and an atomic `<step>.json` under `/root/tayyn-<label>-private/`. `wait`/`status` read those files; a started step is never re-run without `--allow-rerun`                                                                                                                |
| Docker Desktop tmpfs mismatch  | The owner-local rehearsal guard rejected the disposable database                          | The reset guard requires exactly one `tmpfs` mount in `docker inspect` Mounts. Docker Desktop did not report the declared tmpfs in that form; Compose `tmpfs:` shorthand appears in `HostConfig.Tmpfs`, not in Mounts | Declare the data directory as an explicit long-form mount: `volumes: [{type: tmpfs, target: /var/lib/postgresql/data}]`. Release-specific rehearsal scripts must keep this                                                                                                                                                                                     |
| Stale acceptance expectation   | The older private acceptance script failed on the removed approval counter                | The script encoded a pre-1.21 contract                                                                                                                                                                                | Review the private acceptance script against the release notes before maintenance (runbook step 6). Update it in the same release                                                                                                                                                                                                                              |
| CI browser fixture collisions  | CI failed three times on browser workflows                                                | Several tests shared one seeded driver, so state leaked between them                                                                                                                                                  | Each browser workflow creates its own unique actor (commit `67d6423`). New tests must not share seeded actors                                                                                                                                                                                                                                                  |
| Agent rate limits              | Codex delegates hit 429 limits during long runs and stopped mid-task                      | Long runs depended on one provider's quota                                                                                                                                                                            | Delegate release work to Claude agents. ## Android 1.21.1, 2026-10-19

Android 1.21.1 (code 23) shipped as tag `android-1.21.1`. A `v*` tag would have run `container-images.yml` and published server images. Per owner decision it was verified with targeted local tests only; full CI did not run.

The build lessons are now in `android_apk.py`:

- Signing inputs are git-ignored symlinks into the canonical checkout (`android/keystore/*`, release `google-services.json`), with a 0600 copy of the debug `google-services.json`.
- The maps client key is read from a private file.
- `cap sync` rewrites tracked `android/capacitor.settings.gradle`, so the build restores it.
- The APK is checked statically before it is distributed.
