# Domain documentation

This repository uses one root `GLOSSARY.md` and `docs/adr/` for architectural decisions. Read the glossary before domain work and the decisions relevant to the change. If a document is absent, continue without creating placeholder files.

Use the glossary's terms in issues, code proposals and tests. Raise conflicting decisions explicitly before replacing them. Record unresolved product questions in `docs/product.md`, not as settled glossary definitions or ADRs.
