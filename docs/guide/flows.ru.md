# Диаграммы потоков Tayyn Hyzmat

У каждой диаграммы указано, где показано текущее поведение, а где согласованный план. Контракт готовности и расширение на все районы уже слиты; проверка на телефоне остаётся частью выпуска.

## Готовность водителя и смена

Слитый контракт готовности (#85, `2095f56`). Проверки фоновой работы и оборудования на целевом телефоне остаются частью подготовки выпуска.

```mermaid
stateDiagram-v2
  [*] --> GPS_off: нет разрешения или системная геолокация выключена
  GPS_off --> GPS_acquiring: водитель открывает настройки
  GPS_acquiring --> GPS_ready: получена свежая точка
  GPS_ready --> GPS_stale: точка устарела
  GPS_stale --> GPS_ready: получена новая точка
  GPS_ready --> Connecting: водитель нажал «Онлайн»
  Connecting --> Online: API, Socket.IO и первая точка подтверждены
  Connecting --> Offline: нет сети или подтверждения сервера
  Online --> Reconnecting: пропала сеть или GPS
  Reconnecting --> Online: аренда и свежая точка восстановлены
  Reconnecting --> Offline: аренда истекла через 60 секунд
  Online --> Offline: водитель нажал «Офлайн», вышел или закрыл приложение
  Offline --> GPS_ready: локальный GPS всё ещё включён
```

Зелёный значок GPS означает свежую локальную точку. Зелёная кнопка «Онлайн» означает подтверждённую сервером смену. Одно не заменяет другое.

## Создание заказа и выбор предложения

```mermaid
flowchart TD
  A[Диспетчер открывает новый заказ] --> B{Район, телефон и цена TMT заполнены?}
  B -- нет --> B1[Показать ошибку поля]
  B -- да --> C{Режим предложения}
  C -- общий --> D[Открыть очередь района]
  C -- личный --> E[Выбрать свободного онлайн-водителя]
  E --> F{Свежий GPS и достаточный баланс?}
  F -- нет --> F1[Объяснить, почему предложение нельзя создать]
  F -- да --> G[Сохранить резерв и срок 20 секунд]
```

Карта, адрес и точки A/B необязательны. Личный выбор не меняет район заказа.

## Личное предложение и гонка принятия

```mermaid
sequenceDiagram
  participant D as Диспетчер
  participant S as Сервер
  participant V as Выбранный водитель
  participant O as Остальные водители

  D->>S: Создать личное предложение
  S->>V: Безопасные данные, срок = сейчас + 20 секунд
  V->>S: Принять или отказаться
  alt Принято до срока
    S->>S: Заблокировать заказ и водителя, списать цену один раз
    S-->>V: Принято, показать телефон клиента
    S-->>O: order:taken, убрать предложение
  else Отказ до истечения срока
    S->>S: Освободить резерв
    S-->>V: Предложение завершено
    S-->>O: Открыть исходный район до первоначального срока
  else Срок истёк
    S->>S: Освободить резерв
    alt Расширение включено
      S-->>O: Открыть во всех районах
    else Расширение выключено
      S-->>O: Оставить заказ неназначенным
    end
  end
```

После истечения личного предложения выбор диспетчера определяет следующий статус. Поведение слито в #79 (`715b648`):

```mermaid
flowchart LR
  X[Срок 20 секунд закончился] --> Y{Диспетчер разрешил расширение?}
  Y -- нет --> Z[Остановить неназначенный заказ]
  Y -- да --> P[Открыть во всех районах сразу]
  P --> Q[Побеждает первое принятие]
  Q --> R[Отправить всем order:taken]
```

После расширения второго таймера нет.

## Баланс и поездка

```mermaid
stateDiagram-v2
  [*] --> Public
  Public --> Reserved: личное предложение
  Public --> Accepted: первое правильное принятие
  Reserved --> Accepted: выбранный водитель принял до 20 секунд
  Reserved --> Public: ранний отказ, только исходный район
  Reserved --> Public: срок истёк, расширение включено
  Reserved --> Stopped: срок истёк, расширение выключено
  Accepted --> Waiting: водитель приехал
  Waiting --> Started: клиент сел
  Waiting --> Cancelled: отмена водителем или диспетчером
  Started --> Completed: водитель завершил поездку
  Started --> Completed: диспетчер завершил с причиной
  Accepted --> Cancelled: отмена диспетчером
  Started --> Cancelled: текущее API диспетчера, возврат цены
```

Показано целевое правило отмены. Сейчас API дополнительно разрешает водителю отмену из Accepted, это известный пробел. Принудительное завершение записывается как Completed, отдельного статуса Resolved нет. Цена списывается один раз при принятии. После начала поездки водитель отменять не может. При разрыве связи принятый заказ остаётся закреплённым, а новые предложения блокируются.

## GPS, адрес и карта диспетчера

GPS, карта и общий серверный бюджет адресов уже слиты. Включение провайдера проверяется отдельно.

```mermaid
flowchart TD
  G[Свежая GPS-точка] --> R{Точка внутри сохранённого полигона?}
  R -- да --> RI[Назначить район]
  R -- нет --> RO[Показать «Вне района» и координаты]
  RI --> M[Карта и список диспетчера]
  RO --> M
  M --> V{Место видно в приложении или панели?}
  V -- да --> L[Дополнительный поиск адреса по общей квоте]
  V -- нет --> C[Оставить только GPS]
  L --> A[Показать свежий адрес]
  L --> C[При ошибке показать координаты]
```

GPS определяет право на работу. Адрес не определяет район.
