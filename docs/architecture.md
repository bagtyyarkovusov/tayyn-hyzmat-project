# Architecture

The modern browser app uses Vue 3, Vite, strict TypeScript and Vue Router. pnpm manages the root, backend and legacy workspaces. `src/App.vue` owns actor navigation/layout; `app-router.ts` composes existing deep links. `features/auth` owns role sessions, `features/dispatcher` owns dispatcher workflows and `features/driver` owns driver workflows and state. These feature modules hide orchestration behind small interfaces. No generic repositories or speculative DDD layers are introduced.

`shared/api.ts` owns authenticated transport, independent per-role refresh and persisted tokens. Dispatcher and driver have separate Socket.IO connections, so initializing one actor cannot disconnect the other. Logout invalidates that role's pending refreshes and stops the driver session's GPS/timers. Actor screens consume public API contracts, and reconnects reload missed state. `shared/ui` contains components generated by the official shadcn-vue 2.8.2 CLI, using Reka UI. Semantic theme tokens and one persisted light/dark/system preference live in `shared/theme*`; Manrope is self-hosted.

The original Vue 2 application remains in `legacy/`, separately built and served at `/legacy/`. Existing customer deep links redirect there. It retains inherited Firebase/Vuetify dependencies and is not claimed to be TypeScript or modernized. The modern pilot bundles do not import it. `driver.html` remains a dedicated entry; Capacitor asset preparation copies the Vite asset graph. Native behavior still needs device testing.

`backend/src/` contains Express, Prisma/PostgreSQL and Socket.IO. Controllers validate/authenticate and delegate to domain services. JavaScript remains unchecked; region matching, order charge ledger writes and backend tests are strict TypeScript. Backend production runs compiled `dist/server.js`. The schema, migrations and HTTP/Socket.IO contracts are unchanged by modernization.

Driver region matching checks saved polygon rings in `[lat,lng]` order and returns no region outside all saved boundaries; overlapping matches resolve by nearest center. The explicitly named administrative nearest-region helper can fall back to a center, but driver GPS never uses that fallback. Region editing preserves all saved rings, requires explicit save, guards unsaved navigation and checks for server changes before writing. That fresh-read check reduces accidental overwrites but is not an atomic server concurrency guarantee. Test fixtures never access the shared region editor's data.

Acceptance debits the full quoted order price from a driver's synthetic balance; completion does not charge again, cancellation refunds it. `order-charge.ts` owns Decimal arithmetic/ledger writes within existing transactions. Acceptance and cancellation lock driver then order; public audience expansion uses the persisted regional/global markers. The owner-approved decision in issue #10 removes the inherited five-minute automatic acceptance from modern and shipped compatibility drivers. Only explicit manual acceptance claims an order; public regional deadlines and private expansion choices now persist on orders; queue reads, atomic claims, native recovery and Socket.IO use those same audience rules.

The Nginx web image serves browser assets and proxies `/api` and `/socket.io` to the API. Railway follows `main`, and production later uses portable Docker images on a VPS. This migration stays on feature branches without shared deployment.

## Known limits

Cross-region claims/browsing remain [issue #1](https://github.com/bagtyyarkovusov/tayyn-hyzmat-project/issues/1), contrary to agreed own-region policy. Concurrent cancellations or multiple orders for one driver need separate review. Socket.IO alone does not guarantee notifications after a browser closes. Outside-polygon policy and fare semantics remain unresolved in [product scope](product.md). Legacy customer functionality remains available but inherited dependencies still require later assessment.

## Monitoring roster

Monitoring loads every approved-driver page rather than treating the first 100 as the fleet. Location socket events patch known drivers locally without reloading the list; structural events coalesce with a five-second minimum read interval, plus visible-page reconciliation every 30 seconds and on foreground return/reconnect. Reconciliation preserves existing row positions and selection, rejects responses after unmount and keeps newer received location events over older HTTP snapshots. Coordinates remain actual last-reported positions; stale or future GPS never counts as fresh. Availability labels describe online/free/fresh GPS, while the server remains authoritative for offer eligibility and balance policy.

The desktop roster uses compact rows with name/phone/plate search and region/status filters. On narrow screens it opens as an accessible bottom sheet; Escape restores the trigger, and selecting a driver focuses its detail controls. Yandex attribution is unchanged. Live vendor clustering/spiderfying is deferred until it can be verified with a working isolated SDK key; drivers remain accessible through the roster when markers overlap. No address/geocoding requests are added by monitoring.
