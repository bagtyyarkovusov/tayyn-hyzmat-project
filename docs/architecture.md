# Architecture

The modern browser app uses Vue 3, Vite, strict TypeScript and Vue Router. pnpm manages the root, backend and legacy workspaces. `src/App.vue` owns actor navigation/layout; `app-router.ts` composes existing deep links. `features/auth` owns role sessions, `features/dispatcher` owns dispatcher workflows and `features/driver` owns driver workflows and state. These feature modules hide orchestration behind small interfaces. No generic repositories or speculative DDD layers are introduced.

`shared/api.ts` owns authenticated transport, independent per-role refresh and persisted tokens. Dispatcher and driver have separate Socket.IO connections, so initializing one actor cannot disconnect the other. Logout invalidates that role's pending refreshes and stops the driver session's GPS/timers. Actor screens consume public API contracts, and reconnects reload missed state. `shared/ui` contains components generated by the official shadcn-vue 2.8.2 CLI, using Reka UI. Semantic theme tokens and one persisted light/dark/system preference live in `shared/theme*`; Manrope is self-hosted.

The original Vue 2 application remains in `legacy/`, separately built and served at `/legacy/`. Existing customer deep links redirect there. It retains inherited Firebase/Vuetify dependencies and is not claimed to be TypeScript or modernized. The modern pilot bundles do not import it. `driver.html` remains a dedicated entry; Capacitor asset preparation copies the Vite asset graph. Native behavior still needs device testing.

`backend/src/` contains Express, Prisma/PostgreSQL and Socket.IO. Controllers validate/authenticate and delegate to domain services. JavaScript remains unchecked; region matching, order charge ledger writes and backend tests are strict TypeScript. Backend production runs compiled `dist/server.js`. Later order-audience, native-shift, address-budget and finance changes use explicit migrations and public HTTP/Socket.IO contracts.

Driver region matching checks saved polygon rings in `[lat,lng]` order and returns no region outside all saved boundaries; overlapping matches resolve by nearest center. The explicitly named administrative nearest-region helper can fall back to a center, but driver GPS never uses that fallback. Region editing preserves all saved rings, requires explicit save, guards unsaved navigation and checks for server changes before writing. That fresh-read check reduces accidental overwrites but is not an atomic server concurrency guarantee. Test fixtures never access the shared region editor's data.

Acceptance atomically debits the full immutable quoted fare from a driver's synthetic balance and creates the assignment. Start and completion never charge. Only ADMIN dispatchers may cancel NEW, ACCEPTED, WAITING or STARTED orders; assigned cancellations explicitly choose to refund the original debit once or retain it. Completed and cancelled orders return conflicts. The old driver endpoint returns 403, and cancellation review/reoffer/final-cancel actions are retired. Cancellation records actor, time, outcome and refund amount while freeing the driver in the same transaction. Unknown historical outcomes remain unknown. Dispatcher manual completion requires a reason, keeps the charge and records the actor. `order-charge.ts` owns Decimal arithmetic and proof of the original debit. Acceptance and cancellation lock driver, order, then wallet. Assignment-linked unique ledger entries prevent duplicate PAYMENT/REFUND writes. The transactional 1.21 migration converts provable live HELD quotes and rejects ambiguous history before DDL or ledger writes; a database check then forbids new holds. Public audience expansion uses persisted regional/global markers. The owner-approved decision in issue #10 removes the inherited five-minute automatic acceptance from modern and shipped compatibility drivers. Only explicit manual acceptance claims an order; public regional deadlines and private expansion choices now persist on orders; queue reads, atomic claims, native recovery and Socket.IO use those same audience rules.

The Nginx web image serves browser assets and proxies `/api` and `/socket.io` to the API. Railway follows `main`, and production later uses portable Docker images on a VPS. Feature branches isolate changes until reviewed checks pass; merging main triggers the shared Railway deployment.

## Known limits

Cross-region claims follow persisted original-region deadlines and global release. Driver/order locks and conditional writes prevent duplicate assignment and duplicate terminal actions; required operation IDs make dispatcher balance retries idempotent. This protects matching retries, not repeated operations with new IDs. Socket.IO alone does not guarantee notifications after a browser closes. The native renewable lease and foreground service require physical-device verification. Outside-polygon GPS clears the driver region while retaining real coordinates; globally released work remains eligible. Production payment settlement remains outside the synthetic pilot. Legacy customer functionality and dependencies need later assessment.

## Monitoring roster

Monitoring loads every approved-driver page rather than treating the first 100 as the fleet. Location socket events patch known drivers locally without reloading the list; structural events coalesce with a five-second minimum read interval, plus visible-page reconciliation every 30 seconds and on foreground return/reconnect. Reconciliation preserves existing row positions and selection, rejects responses after unmount and keeps newer received location events over older HTTP snapshots. Coordinates remain actual last-reported positions; stale or future GPS never counts as fresh. Availability labels describe online/free/fresh GPS, while the server remains authoritative for offer eligibility and balance policy.

The desktop roster uses compact rows with name/phone/plate search and region/status filters. On narrow screens it opens as an accessible bottom sheet; Escape restores the trigger, and selecting a driver focuses its detail controls. Yandex attribution is unchanged. Live vendor clustering/spiderfying is deferred until it can be verified with a working isolated SDK key; drivers remain accessible through the roster when markers overlap. Visible monitoring locations can request optional addresses through the shared driver-level lookup budget; raw GPS updates do not trigger an unrestricted geocoder request.

## Dispatcher measurements

`GET /admin/overview` preserves the all-time completed trip value and live global fleet snapshot. The separate admin-only `GET /admin/overview/today` reads one Repeatable Read snapshot using a captured server clock. Its returned Asia/Ashgabat date and inclusive/exclusive UTC bounds define the created-today cohort. Terminal rates divide completed/cancelled counts by their sum; unfinished orders remain separate. Acceptance median/p90 use nonnegative persisted acceptance intervals from that creation cohort, including later cancellations, with valid/missing/invalid sample counts. Null means no sample or no terminal denominator.

The live waiting figures include all creation dates. A future private reservation is counted separately; an expired reservation is public only when expansion is enabled, and stopped private offers remain outside live waiting. The analytics query excludes the persisted stopped marker. Public waiting can still be inside the regional visibility window and does not imply global claimability. Oldest waiting age is null for an empty queue. The compact Today section refreshes on relevant order events, reconnect, visibility return and every 30 seconds while visible. Failed loading is distinct from a real zero. These are operational measurements, not payment revenue, historical shift utilization or private-offer conversion statistics. Definitions and deferred instrumentation are tracked in [issue #61](https://github.com/bagtyyarkovusov/tayyn-hyzmat-project/issues/61).
